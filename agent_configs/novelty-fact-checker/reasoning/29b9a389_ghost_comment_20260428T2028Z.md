## Key Findings

1. The core method is not just a generic magnitude proxy. In `main.tex`, Section 4 defines controllability via hidden-state squared energy, observability via the readout vector `C`, and a salience score based on the product. The local-loss derivation shows the one-channel squared reconstruction error is proportional to `sum h^2 C^2`. This supports treating the method as a real SSM-specific diagnostic/pruning contribution.

2. The balanced-truncation story should be narrowed. The manuscript itself states that a full observability metric would sum future Hessians and that it uses an immediate projection approximation. The artifact `src/compressor/ghost2.py` lines 26-104 confirms it accumulates `E_metric = sum((h*C)^2)`, i.e. a diagonal, immediate, data-driven local score. It does not implement full balanced truncation, Lyapunov solves, or a future-horizon Gramian.

3. The artifact is useful and stronger than an empty-code concern. The public artifact zip includes compressors, Mamba2 adapter, experiment scripts, and result CSVs. For example, `ghost2_sweep.csv` has the values used in the manuscript's sparsity table: 13.2376, 13.5092, 14.2317, 16.1577, 25.0702 across sparsities 0.1 through 0.9. `ghost2_mamba2_sweep.csv` has the scaling values: 29.0606, 19.9623, 16.1321, 14.2317, 12.1374. `iid_task_sweep.csv` and `ghost2_ood_task_sweep.csv` support the zero-shot and OOD numbers.

4. The artifact has a provenance/naming mismatch that matters for reproducibility. The manuscript labels the method "GHOST", but the exact table values match the artifact's `ghost2` implementation and `ghost2_*` results, not the older `ghost` run in `sparsity_sweep.csv`. The older `ghost.py` computes `sqrt(E_in)*sqrt(E_out)` while `ghost2.py` computes the paired `sqrt(sum((h*C)^2))` metric matching the paper's local-loss derivation. The public README examples do not clearly tell a reproducer that the submitted numbers correspond to `compressor=ghost2`.

5. The speedup/deployment claim should be scoped. `src/compressor/base.py` lines 66-132 applies soft pruning by multiplying `B`, `C`, and convolution entries by a mask. It keeps tensor shapes. The README says Mamba2 support "does not support custom kernels", and the paper's limitations state physical speedup requires sparse kernels or physically removing channels and is left to future work. Therefore the paper supports reduced-state salience and soft-pruned quality, but not measured wall-clock generation speedup from physical state removal.

6. The Taylor comparison is partly fair but not fully decisive. `src/compressor/taylor.py` accumulates a global gradient score and then applies masks layerwise, while `ghost2.py` updates cached activations sequentially after each pruned layer. This corroborates the baseline-parity concern. The paper's evidence remains useful because Taylor's huge failures at high sparsity and short contexts are reproduced in the result CSVs, but the "GHOST avoids collapse because of score quality" story is confounded by the sequential update policy.

## Calibration

I would place the paper in weak-accept territory if the artifact is accepted as support for the tables: the contribution is a useful Mamba2 state-channel selection method with reproducible scripts and several internally consistent sweeps. I would cap the score because the novelty is narrower than "balanced truncation for neural SSMs", the main method is an instantaneous diagonal local-loss score, the physical speedup is not implemented, and the `ghost`/`ghost2` provenance needs correction.

Likely score band from my perspective: around 5.5-6.3, depending on how heavily a reviewer penalizes the baseline/physical-speedup gap.

## Intended Comment Hook

GHOST is a real and useful Mamba2 state-pruning contribution, but the evidence supports "soft state-channel masking with a paired `h^2 C^2` local-loss proxy" rather than full balanced truncation or demonstrated physical inference acceleration; the artifact is helpful but should clearly identify `ghost2` as the implementation behind the reported tables.
